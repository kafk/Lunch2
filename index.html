Autonomous 8-Stage Architecture
STAGE 01
Discovery
Extracts restaurant names, addresses, and candidate sites via OpenStreetMap Overpass.
STAGE 02 TARGET SPEC
Research & Spec
Identifies official lunch URLs and establishes the TargetSpec: cadence, anchors, and price range.
STAGE 03
Recipe Generation
Synthesizes and dry-runs CSS selectors or HTML weekday parsing strategies.
STAGE 04
Lunch Scraping
Fetches live DOM content, applies selectors, and records raw extracted text.
STAGE 05
Normalization
Transforms raw extractions into structured days, dishes, and price integers.
STAGE 06 VALIDATOR
Source Validation
Independently checks intent, price sanity (90–195 kr), calendar week freshness, and proximity proof.
STAGE 07 QUALITY GATE
Publication Gate
Zero LLM guesswork. Pure Python code routes into SHADOW, ACTIVE, or REPAIR.
STAGE 08
Exception Queue
Human review is strictly an exception queue for items that fail 2 automated repairs.

Why the Pipeline Changes Everything

Comparing naive text extraction against deterministic intent validation.

❌ Previous Failure Mode (Selection Trap)

  • Scraper only checked extraction: As long as text contained food words or prices, it assumed it succeeded.
  • Dinner menus leaked: À la carte dishes at 345 kr were published onto Lunchdejt.
  • Booking widgets extracted as dishes: Opening hours ("tisd 11.30-20.00") became fake menu entries.
  • Human choked with volume: Required approving 100% of discovered candidates manually.

✔ Autonomous Validation & Gate

  • TargetSpec generated first: Research identifies what lunch looks like before code is generated.
  • Selection & Intent verification: Compares candidates against negative signals and lunch anchors.
  • Deterministic price sanity: Rejects dishes exceeding typical Swedish lunch pricing (90–195 SEK).
  • Shadow mode testing: Must pass two scheduled scrapes across time before public activation.
  • Human is an exception queue: Only inspects the 5% that fail automated repair attempts.
